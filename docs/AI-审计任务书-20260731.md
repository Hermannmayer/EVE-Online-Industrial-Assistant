## 1. 项目背景

**EVE 商人助手** — 给 EVE Online 玩家用的桌面工具（Windows 为主），核心价值：

1. **市场价格查询** — 四大贸易中心（Jita/Amarr/Dodixie/Rens/Hek）物品买/卖价一键查询
2. **制造利润计算** — 基于游戏蓝图（Blueprint）的 BOM 展开、材料成本、安装费、利润率计算
3. **贸易评分** — 跨区域价差、成交量、风险综合评分，帮玩家决定买哪卖哪
4. **估价** — 剪贴板粘贴物品列表 → 批量查价
5. **库存管理** — 机库物品 CRUD、价值统计、蓝图导入
6. **生产计划** — 排程、BOM 材料汇总、甘特图、代采购管理
7. **价格监控** — 关注列表 60s 定时刷新，价格变动通知
8. **合同/物流/精炼** — 游戏合同管理、运费估算、矿物精炼计算

数据来源：**ESI API**（EVE 官方 REST API，`https://esi.evetech.net/latest`）+ **SDE**（静态数据导出包，含物品/蓝图/星系全量静态数据）。本地 4 个 SQLite 库缓存。

## 4. 核心流程（审计必读）

### 4.1 启动流程（Main.py）
```
ensure_dirs → _migrate_split_db（旧 items.db→4库）→ _migrate_blueprint_db（蓝图表→blueprint.db）
→ init_db（inventory_manager）→ excepthook（崩溃转储 ~/.eve-assistant/crashes/）
→ Qt 消息过滤器 → 单实例锁 → MainWindow → app.exec()
```

### 4.2 价格拉取（services/workers/getprices.py）
两阶段：先拉 `/markets/prices/` 全量兜底（1 次请求）→ 并发拉 4 区域订单簿，真实买卖价覆盖。
`_PAGE_CACHE` 模块级 dict 缓存分页数。

### 4.3 制造利润计算链路
```
UI(industry_view) → container.scoring_service() → ScoringService
→ manufacturing_calculator（公式） + bom_expander（BOM 展开）
→ price 来自 pricing_service / 模块级 get_price
```

### 4.4 UI 线程模型
所有网络/DB 操作在 QThread（ui_pyside6/workers/），Signal 通知 UI。评分有 TTL 缓存（500 条 / 30min）。

## 5. 已识别的代码特征（待验证疑点，不是定案）

以下是我（本次扫描）注意到的模式，**请逐条验证是否成立、评估影响、并顺藤摸瓜找同类问题**：

### A. 模块级单例 vs DI 容器双轨制
- `core/container.py` 已实现完整 IOC 容器（懒加载 + RLock 双检），15 个服务
- 但以下文件仍存在 **import 时 `db = get_db()`**（模块加载即绑定连接）：
  - `services/scoring_service.py:48`
  - `services/logistics.py:22`（还有 `_pricing = _PricingService(get_db())`）
  - `services/bom_expander.py:25`
  - `services/inventory_manager.py:9`
  - `services/production_scheduler.py:18`
  - `services/watchlist_manager.py:7`
  - `services/price_history.py:21/75/101`
- `services/scoring_service.py:123-130` 模块级单例 `_scoring_service_instance`
- **疑点**：容器创建的实例和模块级函数用的实例是否是同一份？双轨是否导致缓存/连接不一致？

### B. 巨型文件
| 文件 | 行数 | 观察 |
|---|---|---|
| `ui_pyside6/views/estimate_view.py` | 1136 | 单文件多职责？ |
| `ui_pyside6/views/all_items_view.py` | 1085 | |
| `ui_pyside6/main_window.py` | 1057 | 13+ 视图注册全在这？ |
| `services/scoring_service.py` | 1024 | ScoringCache + ScoringService + 模块级函数三合一 |
| `ui_pyside6/views/char_settings_view.py` | 1013 | |
| `ui_pyside6/views/contract_view.py` | 938 | |
| `ui_pyside6/theme.py` | 684 | 颜色主题单文件 |

### C. compat shim 层层转发
`views/query_view.py`(265B) / `views/compare_dialog.py`(734B) / `views/inventory_view.py`(871B)
是旧路径转发到新子包（query/、compare/、inventory/）。但 `main_window.py:418/884` 仍从旧路径 `query_view` 导入。
**疑点**：转发层何时能删？有没有从新路径和旧路径同时导入导致两份实例/两份状态？

### D. 服务层反向依赖 UI 层
`core/container.py` 的 `char_config_resolver` 属性内嵌 `_char_data_provider` 闭包，
`try: from ui_pyside6.views.char_settings_view import get_character` — **services/core 层 import UI 层**。
**疑点**：分层倒置，UI 卸载/重构时容器会不会断？还有没有别的反向依赖？

### E. 数据层直接暴露
UI 大量使用 `get_container().db.direct_connect("mkt")` / `connect("ref","mkt","user","bp")`
直接写 SQL（如 `query_search.py:615/647`、`main_window.py:89`），绕过 repositories 层。
**疑点**：repositories 层（item/market/blueprint/plan）与直接 SQL 的边界在哪？是否有重复查询逻辑？

### F. services/__init__.py 与 core/__init__.py 为空
无公共 API 边界，消费者可以 `from services.xxx import yyy` 任意深度导入。

### G. workers/ 与 tools/downloaders/ 重叠
`services/workers/`（getprices/getcontracts/getindustry，运行时拉取）
vs `tools/downloaders/`（getitems/getblueprints/geticon/getimplantdata，初始化一次性导入）。
**疑点**：是否只是阶段划分？有没有重复的 HTTP/进度条/写入逻辑可以合并？

## 6. 审计维度（逐项给出结论）

按以下 8 个维度审计，**每个维度都要有：现状描述 + 问题列表（文件:行号 + 严重性 P0/P1/P2 + 影响 + 修复建议）**。

### 6.1 设计架构
- 分层是否清晰？依赖方向是否正确（UI→services→data，有无反向）？
- 4 库分离是否合理？ATTACH DATABASE 的多库 JOIN 有没有坑（如事务边界、连接池）？
- 单实例锁、热重载、崩溃转储机制是否健壮？

### 6.2 流程
- 启动流程：迁移脚本的幂等性、失败恢复、启动耗时
- 价格拉取：并发控制、限流（ESI 要求 ≤20 req/s）、失败重试（tenacity 用法）、进度恢复
- 制造计算：BOM 展开深度、公式正确性（对照 EVE 现行机制：ME/TE、结构加成、技能）
- 关注列表 60s 定时器：泄漏？重复请求？UI 卡顿？

### 6.3 设计模式
- IOC 容器是否被一致使用？模块级单例/全局 dict（如 `_PAGE_CACHE`）有哪些？
- QThread Worker 模式是否统一？有没有裸线程/阻塞 UI 的地方？
- 主题热切换机制（add_theme_listener）有没有泄漏（监听器未注销）？

### 6.4 功能完整性
- 对照 `EVE-PROJECT-STATE.md` 功能清单，逐项验证是否真实可用
- 占位/未实现功能（`docs/placeholder_clock_audit_20260703.md` 是 7-03 旧报告，**请重新扫描**所有 `print("功能开发中")` / `QMessageBox.information(...开发中...)` / `pass` / TODO）
- 异常分支：网络失败、数据库损坏、SDE 数据缺失时 UI 表现

### 6.5 Bug 排查
- 重点查：多线程共享状态（DB 连接跨线程）、SQL 注入风险（f-string 拼 SQL）、
  时区/时间处理、浮点精度（利润/税率）、Qt 对象生命周期（C++ 对象已删除崩溃）、
  缓存一致性（评分缓存 TTL 过期后是否重建正确）
- 用 `search_files`/grep 扫：`except: pass`、裸 `except`、`QTimer` 未 stop、`get_container()` 在 import 时调用

### 6.6 测试
- 603 个用例覆盖了什么、缺什么（UI 层/网络层/数据库迁移）
- conftest.py 的 fixture 有没有 session 级共享状态污染
- 有没有测试依赖真实 ESI 网络（不可重复）

### 6.7 性能
- 大文件里的同步 DB 调用是否在 UI 线程？
- 图标缓存、SDE 加载（600+MB 静态数据）有没有内存峰值问题
- 价格拉取 4 区域并发量级

### 6.8 数据一致性
- 4 库之间的外键关系有没有保证（物品 ID 跨库引用）
- 市场数据快照过期策略（TTL/定时刷新）
- 评分缓存与价格更新之间的失效联动
