## 项目定位

一个基于 PySide6（Qt for Python）的桌面应用程序，为 EVE Online 玩家提供多区域市场价格查询、物品搜索、制造利润计算、贸易评分和库存管理功能。

---

## 技术栈

| 层级 | 选型 | 说明 |
|------|------|------|
| GUI | PySide6 ≥ 6.5 | Qt6 Python 绑定 |
| 数据库 | SQLite3 + aiosqlite | 4 个独立库，异步写入 |
| HTTP | aiohttp | 并发请求 + ESI 限流 |
| 重试 | tenacity | 指数退避 |
| 打包 | PyInstaller | 单可执行文件分发 |
| 日志 | 自封装 `_Logger` | 控制台 + 文件双输出 |
| 工具 | Pillow, pyperclip, tqdm, pyyaml | 图标、剪贴板、进度条、YAML |
| 语言 | Python 3.14 | |
| 格式化 | Ruff | lint + format 合一 |

## 数据库架构

### 4 库拆分策略

按数据生命周期和变更频率分为 4 个独立 SQLite 文件：

```
database/
├── reference.db   ← 静态参考数据（一次性写入，只读）
├── blueprint.db   ← 蓝图数据（一次性写入，只读）
├── market.db      ← 市场价格（频繁覆写）
└── user.db        ← 用户数据（增删改）
```

### reference.db

| 表 | 内容 |
|----|------|
| `item` | 物品基础信息（type_id, 中/英文名, group, market_group, volume, iconID） |
| `market_tree` | 市场分类树 |
| `industry_system_costs` | 工业系统成本指数 |
| `item_dogma` | 物品 dogma 属性 |

### market.db

| 表 | 内容 |
|----|------|
| `market_prices` | 实时订单价格快照（buy_price, sell_price, buy_volume, sell_volume, fetch_time） |
| `market_volume_snapshots` | 成交量快照 |

### blueprint.db

| 表 | 内容 |
|----|------|
| `blueprint_activities` | 蓝图活动基本信息 |
| `blueprint_materials` | 蓝图材料清单 |
| `blueprint_products` | 蓝图产出 |
| `blueprint_skills` | 蓝图所需技能 |

### user.db

| 表 | 内容 |
|----|------|
| `hangars` | 机库定义（矿仓/组件仓/产品仓等） |
| `inventory_items` | 库存物品（type_id, 数量, 加权平均成本） |
| `user_blueprints` | 用户拥有的蓝图（ME/TE/数量） |
| `production_plans` | 生产计划 |
| `user_skills` | 角色技能 |

跨库查询通过 `ATTACH DATABASE` 实现，详见 `services/database_manager.py`。

## 架构模式

扁平架构：**页面 + 后台 Worker 线程 + 直接 SQL**

```
Main.py
  │
  └─ MainWindow (QMainWindow)
       ├── QTreeWidget (侧边导航)
       ├── QStackedWidget (内容区)
       ├── QStatusBar (状态栏)
       └── 后台 QThread (Worker 模式)
            ├── PriceUpdateWorker
            ├── SearchWorker
            ├── OrderFetchWorker
            └── BPMatWorker
```

设计原则：
- 每个 QThread 只做一件事，用完即弃
- 页面之间通过 MainWindow 传参
- 极少抽象层，services/ 下是函数集合，非类

### 3.3 价格拉取逻辑

```
OnTimer（每 ~60 秒）:
    for each region in 交易区域:
        1. 检查该区域上次拉取时间
        2. 如果距今时间 > 过期阈值:
            3. 拉取 /orders/?order_type=sell 所有分页
            4. 拉取 /orders/?order_type=buy 所有分页
            5. 聚合计算:
                - sell = min(卖单价格)  → 卖一价
                - buy = max(买单价格)   → 买一价
                - sell_vol = sum(卖单量) → 卖方深度
                - buy_vol = sum(买单量)  → 买方深度
                - sell_count = 卖单数量  → 卖方热度
                - buy_count = 买单数量
            6. 更新缓存 PV/PVMore 表
            7. 标记该区域更新完成
```

### 4.1 制造流程总览

```
用户选择产品
    │
    ▼
1. 查找蓝图（blueprints.BP_Main）
    │
    ▼
2. 展开 BOM（材料清单）
    ├─ 2.1 直接材料（blueprint_materials 表）
    ├─ 2.2 子件递归（Chain_M_MID 产业链展开）
    │   ├─ 每层查子件的蓝图
    │   ├─ 如果子件仍是中间件 → 继续展开
    │   └─ 直到基础材料（矿石/反应物）
    └─ 2.3 反应材料（IsReact=1/2 标记）
    │
    ▼

    ├─ 材料买入价（原料区域 PriceMatRegion）
    └─ 产品卖出价（产品区域 PriceProRegion）
    │
    ▼

    ├─ 材料成本 = Σ(材料数量 × 单价)
    ├─ 时间成本 = 制造时间 × ISK/秒费率
    ├─ 运费 = 体积 × 运价
    └─ 税费 = (成本 + 运费) × 税率
    │
    ▼
5. 利润分析
    ├─ 毛利润 = 收入 - 成本
    ├─ 毛利率 = 利润 / 成本 × 100%
    └─ ROI = 利润 / 投资 × 100%
    │
    ▼
6. 排产计划（可选）
    ├─ 选择设施（GClass75 设施管理）
    ├─ 分配角色（GClass1 角色税率）
    ├─ 分配制造槽（GClass80 产能计算）
```

### 4.5 批量排产算法

#### 4.5.1 约束条件

```
输入: 产品列表 [{type_id, runs, parallels, facility, char}, ...]
约束:
  1. 每个角色有固定数量的制造槽（由技能决定）
     - 批量生产学 → 每级 +1 槽
     - 高级量产技术 → 每级 +1 槽
     - 基础槽数 = 1
  2. 每个设施有最大并行数（挂起点限制）
     - NPC 空间站：~10 个
     - 玩家哨站：更多
  3. 每个产品有制造时间（受 TE + 工业指数影响）
  4. 某些产品只能在特定设施制造
  5. 时间线约束：一个槽同一时间只能做一个产品
```

#### 4.5.2 贪心排产算法（Dlg_IndutMultiAuto）


```
                              × (1 - 空间站税)

每种矿石有固定的成分产出表:

- 等等...
```

#### 7.2.2 精炼产出计算

```
输入矿石 + 数量
  │

查矿石成分表（每种矿石固定成分）
  │
  ▼
实际产出 = 基础产出 × 实际回收率
  │
  ▼
输出各种矿物及数量

同时计算:

- 判断值不值得精炼
```

### 10.2 ESI 定价拉取（DataUpESI）

#### 10.2.1 拉取流程

```
DataUpESI 是一个带 UI 的窗口，运行主循环:

OnLoad:
  1. 从 RegionMark 读取所有配置的区域
  2. 初始化 PV / Vol / PVMore / VolMore / TimeStamps 缓存表
  3. 启动 market_timer（~60 秒间隔）

OnTimer:
  for each region in 交易区域列表:
    1. 查 TimeStampsWEIGHT[region].DelaySec
    2. 如果距今 > DelaySec:
      3. 拉取 /markets/{region}/orders/?order_type=sell（多页）
      4. 拉取 /markets/{region}/orders/?order_type=buy（多页）
      5. 聚合计算:
         sell = min(订单价格)       // 最低卖价
         buy = max(订单价格)        // 最高买价
         sell_vol = sum(卖单剩余量) // 卖方深度
         buy_vol = sum(买单剩余量)  // 买方深度
         sell_count = 卖单数       // 卖方挂单密度
         buy_count = 买单数
         sell_avg = 加权均价
         buy_avg = 加权均价
      6. 写入 PV/PVMore 表
      7. 拉取 /markets/{region}/history/（成交量历史 30 天）
      8. 计算 volume_30, avg_price_30, bs(买卖比)
      9. 写入 Vol/VolMore 表
      10. 标记该区域更新完成
      end
  end
  所有区域完成 → 更新 TimeStamps → 标记 ready
```

#### 10.2.2 缓存过期判断

```csharp
// GClass138.smethod_1 — 判断缓存是否过期
// 输入: long_0(区域ID), int_0(物品ID)
// 输出: bool
// 逻辑:
//   elapsed = 当前时间 - TimeStamps[region].UpTime
//   如果 elapsed > DataUpESI_Volume.long_0 (= 900 秒=15 分钟)
```
